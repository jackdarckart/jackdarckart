Songwünsche, Feedback, Fehler, Sicherheit

Kontaktwege ohne Drittanbieterformular und ohne versteckte Datensammlung.

Diese Seite bereitet ausschließlich lokale Mailto- oder GitHub-Issue-Links vor. Sie eignet sich für Songwünsche, allgemeines Feedback, technische Fehler oder Sicherheitsmeldungen und erklärt gleichzeitig, wann welche Angabe hilfreich ist.

Songwunsch & Feedback

Direkt, nachvollziehbar und datenschutzfreundlich.

Deine Eingaben werden nicht automatisch gespeichert, nicht im Hintergrund versendet und nicht an eingebettete Drittdienste weitergereicht. Erst dein Klick auf E-Mail oder GitHub Issues löst eine lokale Aktion im Browser aus.

Hilfreiche Angaben

Ein klarer Betreff, eine kurze Beschreibung und bei technischen Fehlern idealerweise Browser, Gerät und sichtbarer Status helfen am meisten.

Sicherheitsmeldungen

Für potenzielle Sicherheitsprobleme sind Zeitpunkt, betroffener Bereich, beobachtetes Verhalten und – wenn relevant – externer Link oder Streamweg hilfreich.

Senderseite auf laut.fm

Du kannst einen Songwunsch oder Feedback lokal als E-Mail oder GitHub-Issue vorbereiten.

Wenn keine Mailadresse in der Konfiguration hinterlegt ist, bleibt GitHub Issues der verfügbare Fallback.

Plattform-Links & Hinweise

Nur verifizierte Ziele und klare nächste Schritte.

Zusätzliche Ziele wie laut.fm, Direktstream oder GitHub Issues stammen aus der statischen Konfiguration. Ohne bewusst gesetzte Links wird hier nichts erfunden.

Wann sollte ich GitHub Issues statt E-Mail nutzen?

Wenn du technische Probleme nachvollziehbar dokumentieren möchtest oder wenn aktuell keine Mailadresse gepflegt ist, ist GitHub Issues der klar sichtbare und versionierbare Fallback.
